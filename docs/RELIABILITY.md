# 保存与同步可靠性

## 阶段 0：保存状态（第一部分）

Markdown 的 `Saved` 表示当前会话产生的 Yjs 更新均已收到对应
`clientUpdateId` 的服务端持久化 ACK，且连接在线、房间初始化完成。

- 用更新 ID 集合记录待确认修改；部分、重复、乱序和未知 ACK 不确认其他修改。
- 重连初始化不清除待确认集合。连接上线后，完成房间初始化之前仍显示重新连接。
- Markdown cache ACK 仅确认派生文本，不确认 Yjs 更新，也不决定正文保存状态。
- 每次本地 Yjs 更新立即刷新状态和账号退出时使用的未保存标记。
- 离线时显示离线，即使此前修改已确认，也不暗示连接仍然正常。

## 尚未完成的可靠性边界

已打开文档的未确认正文更新现在写入本地 outbox；网络恢复后重新打开时可恢复，见下文。
整站离线启动不在当前承诺内；独立恢复入口、旧代际记录管理与导出水位见下文。
正文已保存不等于导出缓存已经追平；导出会单独检查缓存版本。

## 验证

`web/e2e/markdown-save-state.spec.ts` 包含状态单元测试与真实编辑器测试。
后者转发 WebSocket 流量但扣留正文 ACK，验证部分/重复 ACK 以及缓存 ACK
均不能提前显示已保存，全部确认后才显示已保存，刷新可恢复正文。

## 阶段 0：压缩后的重试确认

增量迁移 `0005_markdown_receipts.sql` 新增 `markdown_update_receipts`，保存
`(item_id, client_update_id) → seq`，并从现存更新日志回填。正文更新与确认记录
在同一事务提交，任何一步失败都回滚。重复请求仍先检查当前用户写权限。

快照压缩只删除更新二进制，不删除确认记录；服务重启后相同 ID 仍返回原 seq，
不会重新追加更新。确认记录不包含正文，但随编辑次数增长；当前不定时清理，
避免给尚未定义的离线重试期限设置隐含失效时间。删除 Item 时级联删除确认记录。
现有显式 Markdown 重置会同步清除确认记录，与其清除旧更新日志的行为一致。

升级前已被压缩删除的 ID 无法回填。旧更新不能跨正文重置自动重试；后续的代际校验会拒绝它们，客户端保留本地副本。

测试：`internal/core/markdown_receipts_test.go` 验证压缩、重启、权限、Item 隔离、
级联删除和失败回滚；`internal/db/db_test.go` 验证已有数据回填与幂等迁移。

## 阶段 0：内容代际隔离

迁移 `0006_markdown_generation.sql` 为已有正文增加 `generation=0`，不转换或删除内容。
新建文档同样从 0 开始；显式正文重置在清除旧更新 / 确认记录的事务内递增代际。
正文读取在同一读事务中获取代际、快照和更新，避免重置并发时拼接不同内容。

`markdown.init` 返回代际。正文更新、Markdown cache、snapshot commit 必须携带
该编号，服务端在各自写事务内验证；过时代际返回 `GENERATION_CHANGED`，没有
编号返回 `GENERATION_REQUIRED`，不尝试把旧更新迁入新正文。

前端重连发现代际不同，或收到上述错误，会停止编辑与持久化发送，保留当前
编辑器供阅读和下载本地 Markdown 副本。不会先合并新代际再提示错误。
下载副本仍可能含私有资源 URL，不是带附件的可移植导出包。

升级兼容边界：此次协议增加必填字段。服务和内嵌前端一起升级；升级前已打开
的页面需刷新，缺少代际的写入会被拒绝。旧前端不能识别新错误提示，因此升级
前应先让所有协作者确认保存并关闭编辑页。浏览器持久化恢复见下节。


## 阶段 0：浏览器 outbox

使用同源 IndexedDB 数据库 `madoc-markdown-outbox`，以 origin、用户 ID、Workspace ID、
Item ID、generation 隔离。用户和内容 ID 由服务实例生成；新安装不会沿用另一数据库的 ID。
每次正文修改只追加 Yjs 增量及稳定 clientUpdateId；本地事务完成后才发送，收到匹配 ACK
后将该增量从待提交状态改为已确认恢复数据。传输失败不从队列移除；在线时约每 3 秒
重试，重连先 join 校验代际，再重放原 ID。瞬时 awareness 不进入 outbox。

本地恢复记录包含服务端基线和增量，确保离开、刷新或关闭标签页后还能重建待提交正文。
多个标签页追加独立记录，不覆盖彼此的文档快照。每累计 200 次增量保存尝试合并已确认
恢复记录，仍待确认的 ID 独立保留。配额等写入失败会停止编辑，提供下载和本地保存重试；
重试时恢复快照及待提交记录在一个事务中写入，任何中途失败都回滚。

离线且所有待提交修改已完成本地事务时才显示“已保存到此设备，待同步”。有尚未写入本地
的修改时，刷新 / 关闭触发离开提示；应用内切换先等待本地写入结束，失败时要求明确确认。
成功持久化的待提交修改允许切换文档，重新打开后继续提交。退出账号不删除其他账号的记录，
其他账号不会自动读取或提交这些修改。本地数据不是独立备份，清理站点数据仍会删除它们。

同代际恢复先合并本地记录和服务器状态；旧代际有 pending 时保留旧正文为只读救援，禁止
自动提交到新代际。当前 viewer 有自己的未提交修改时同样进入只读救援。已打开会话收到
权限 / 文档失效或超限拒绝时停止继续提交，保留本地内容。整站离线刷新和离线首次打开
不在承诺范围：需要恢复网络、通过账号和 Item 的 REST 校验后才能重新打开编辑器。

缓存和快照不得包含未确认的本地修改；快照请求的 baseSeq 还必须与当前已应用 headSeq
一致。缓存从当前编辑器即时序列化，不依赖延迟的展示文本。

验证入口：`markdown-outbox.spec.ts`、`markdown-generation.spec.ts` 和
`markdown-save-state.spec.ts`，覆盖未发送 / ACK 丢失、刷新、切换、双标签关闭恢复、
账号隔离、本地配额失败、事务中途失败回滚、重试和代际救援。


## 阶段 0：独立本地恢复入口

个人设置的“本地恢复”查询仅限当前 origin / 用户的 IndexedDB 索引范围。无需读取原文档
即可重建并下载本地正文，适用于 Item 被删除、权限被移除以及旧代际的待提交修改。
使用现有编辑器的 schema 与 serializer，在不建立 WebSocket、不写服务器的情况下生成
Markdown；预览只展示源码，不加载正文中的远程图片或其他资源。

outbox 的新记录附加可选 title / updatedAt，兼容旧记录，不改 IndexedDB 版本。
选择副本后可下载，并可显式处理已被服务器替换的旧代际：REST 返回 generation 供检查，
仅更新选定 ID 的 archived 标记，不删除本地二进制。当前代际或无法读取服务器版本时
拒绝处理；并发新增记录不受影响。旧副本保留在列表，编辑会话不再自动重试已处理 ID。

入口仍依赖当前账号登录和应用已加载；它不提供跨账号查看，也不实现整站离线启动。
验证见 `markdown-recovery.spec.ts`：删除后恢复、Markdown 语义保留、零原 Item 请求、
旧代际处理 / 当前代际拒绝、标记后副本保留、账号切换隔离及桌面 / 390px。

## 阶段 0：导出水位

编辑器导出先等待当前本地更新全部确认，再固定 generation / minSeq，并请求刷新
Markdown cache。服务端在同一读事务内检查代际、cacheSeq 和 headSeq，只有缓存达到
请求水位才返回正文；未指定水位时要求追平读取时的 headSeq。响应禁用 HTTP 缓存，
并携带实际代际和 cacheSeq。明确水位是最低版本要求，允许导出包含后续已确认修改，
不承诺冻结点击时的精确历史版本；固定水位后产生的新编辑不属于此次最低保证。

缓存未追平时客户端重试，总等待上限 8 秒。离线、权限失败、代际改变或超时不会自动
下载旧缓存，而是提示重试或显式“下载本地副本”。本地副本从当前编辑器序列化，文件名
带“本地副本”，可能含未同步内容及私有资源 URL。切换或关闭编辑器中止导出请求。
viewer 只能读取已存在的缓存，不发起缓存写入；缓存滞后时也遵循等待和本地副本流程。

验证：`internal/core/markdown_export_test.go` 与 `markdown-export.spec.ts` 覆盖缓存滞后、
最低水位、重置、权限隔离、部分 ACK、超时重试、viewer 零写入、登录失效及移动端离线副本。

## 阶段 0：已有连接的权限失效

房间订阅不是永久授权。Markdown / Whiteboard 正文广播、光标 / awareness 转发和成员
列表发送前，服务端重新校验接收者的 session 和当前 Item 读权限；瞬时消息也校验发送者。
会话过期、账号禁用、成员移除和 Item 删除后，不再向失效连接排入新内容，移除其 Item
订阅并返回错误。已经在权限有效时排入连接的消息不承诺撤回。成员列表过滤失效成员。
查询失败时不发送内容；客户端可在服务恢复后重新打开文档。

现有持久化写权限检查保持独立，成员降为 viewer 或移除后，已有连接的正文、缓存、快照
和白板写入均拒绝。Markdown 收到权限拒绝后停止编辑，保留当前正文及未提交本地记录，
支持下载副本。已接收内容不会因撤权而从设备上远程抹除。

测试：`internal/realtime/access_test.go` 覆盖两种内容的撤权广播、过期会话、禁用账号、
删除 Item、瞬时消息与成员列表、降级及移除后的持久化写入拒绝；
`markdown-permission-revocation.spec.ts` 验证真实双页面撤权后无新正文泄漏且未提交内容可救援。

## 阶段 0：真实进程恢复回归

`web/playwright.restart.config.ts` 使用独立测试进程，不复用普通 E2E 的 webServer。
Markdown 测试分别向真实二进制发送 SIGTERM / SIGKILL，覆盖正文发送前失败与服务端
已写入但 ACK 丢失两种情况，停服期间继续编辑，重启后验证稳定更新 ID、原确认序号、
导出、会话与刷新后的正文。测试只终止自己启动的进程，数据位于独立临时目录。

备份恢复用例通过正式 maintenance CLI 停服备份，再初始化另一目录并恢复，检查
Markdown、真实画布创建的白板元素、附件二进制及 server secret / 会话保留。
这是进程与文件持久化验证，不等同于断电或磁盘硬件损坏模拟。运行步骤见 `BUILD.md`。
