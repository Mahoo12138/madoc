# madoc 产品演进路线

本路线落实 `madoc_功能设计与开发阶段计划_2026-09-23.md` 的持续开发任务。
`PLAN.md` 保留原架构迁移历史；具体完成证据记录在 `STATUS.md` 与相关设计文档中。
阶段通过后才推进下一阶段，每一部分独立验证并提交。

## 阶段 0：可靠保存与可重复验证（已验收）

验收范围：可信 ACK 状态、持久化待提交更新、重连 / 刷新 / 关闭恢复、存储失败救援、
Markdown 导出水位、已有连接撤权、真实服务重启和备份恢复、固定提交发布检查。

固定提交 `9c908d7845c645180c5194a06d3aae18e2f840fb` 的完整门槛通过，详见发布记录。
协议及支持边界见 `RELIABILITY.md`、`WHITEBOARD.md`，完整检查方法见 `RELEASE.md`。
阶段 0 候选未包含回收站、完整离线工作区、带附件迁出包或产品级版本历史。

## 阶段 1：找得到，误删可救（已验收）

已完成软删除 / 批次恢复服务与 API 基础，见 `CONTENT_LIFECYCLE.md`。owner 彻底删除保护与批次详情 API 已完成；回收站界面已接入，目录通知、前端共享连接与失效内容救援已接入。搜索 core / REST、快速打开与搜索界面已完成，短词、权限、缓存水位和键盘操作见 `SEARCH.md`。个人收藏与最近访问的 migration / core / REST 已完成，见 `PERSONAL_NAVIGATION.md`；桌面 / 移动端导航已接入。固定提交 `db903af` 完整功能门槛通过，见 `RELEASE.md`。

按以下可验收部分推进：

1. 增量迁移与 Item / 子树软删除；保留删除批次、原层级和附件，所有正常读写路径过滤已删除内容。
2. 批次恢复与 owner 手动彻底删除；原父级失效时由用户选择新位置，不恢复早先独立删除的子项。
3. 回收站 UI、目录元数据事件及多客户端失效反馈；打开中被删除的内容停止写入并保留本地救援。
4. 当前 Workspace 快速打开与搜索；标题 / 路径及 Markdown 派生正文，中文短词、权限和索引水位明确。
5. 个人收藏与最近访问；用户之间隔离，删除 / 恢复后的导航入口正确变化。

验收：事务内恢复整棵本次子树、附件不丢、无跨工作区泄漏、viewer 不可写、
旧页面不能向已删除 Item 提交，搜索重命名 / 删除 / 恢复及中文短词正确。
第一版采用手动流程，不设未经确认的 30 天自动清理策略。Workspace 删除保留独立名称确认。
