# 可移植内容原子导入

## 已确认的行为

- 新建独立内容，不覆盖既有 Item；保留包内目录、正文、白板和附件引用。
- 整组成功才出现，失败不留下半组内容。
- 客户端整组选择上限：压缩文件合计 256 MiB、解压合计 512 MiB、5000 个文件和目录（含清单）。
- 内容包、附件包和包集清单必须整组通过校验；单独的内容分包不代表完整包。

桌面与手机的“新建内容 → 导入内容包”已接入单 ZIP / 完整包集预览、目标位置与名称冲突检查、
确认导入和原请求重试。数据库事务、附件协调、浏览器内容编译与引用映射共同完成整组写入。
单篇 Markdown 附件 ZIP 的格式适配仍待实现；`.md` 单文件导入继续使用原入口。

## 数据库提交边界

`core.ImportContent` 接受一棵新树、目标父目录和已经由服务端验证的附件元数据。在一个 SQLite
事务内完成：当前写权限及账号启用状态检查、目标目录检查、ID / 根名称冲突检查、所有 Item
及初始 Markdown / 白板状态写入、附件元数据写入和成功回执写入。任何一步失败均回滚。

- 导入内只允许一个根，所有其他父级必须来自本组且为文件夹；拒绝缺失父级、多根与环。
- 输入可为非拓扑顺序；写入时父级优先，同级顺序保留输入顺序。
- 目标父目录必须是当前 Workspace 的活动文件夹，或 Workspace 根目录。
- Item / 附件使用新 UUID；已有 ID（包括回收站中的 Item）发生冲突时拒绝，不更新旧记录。
- 新根名称与目标位置的活动同级名称完全相同时拒绝，供前端提示改名；包内原有重名保留。
- Markdown 必须包含自足初始 Yjs 快照及文本，Go 不解析 Yjs；白板必须包含有效 scene。
- 服务层限制 Item 与附件数合计最多 5000，初始快照 / Markdown 文本 / 白板 scene 与附件
  原始大小合计不超过 512 MiB。转换出的初始协作快照也占用额度，不能仅以压缩包大小判断。
- 附件只能绑定本次导入的 Item。存储路径由服务端生成，包含目标 Workspace ID、导入尝试
  UUID 与附件 UUID；客户端不能指定。内部存储路径不参与请求摘要，重试的新尝试不改变请求身份。

## 响应丢失与重复请求

新增 `content_imports` 保存请求 UUID、Workspace、创建用户、请求 SHA-256、根 Item ID
和创建时间。请求摘要包含目标、所有 Item 初始状态与附件实际摘要；同一请求 UUID 只接受
同一用户、同一 Workspace、完全相同的请求数据（包含顺序），不会因客户端重试再创建一组。

回执与内容同事务提交。成功后相同请求返回原根 ID 与 `replayed: true`；不同请求内容或不同
调用者复用同一 UUID 返回冲突。重放仍检查当前写权限及账号状态，不能借旧回执绕过撤权。

Item 删除或彻底删除不清除回执，避免延迟重试重新生成已删除的内容；Workspace 删除会级联
清除其回执。目前不按时间自动清理回执。新连接 / 新进程从数据库读取回执，不依赖内存缓存。

## 附件文件与数据库联合提交

当前服务层的 `ImportAsset` 是内部可信输入，不可直接把客户端声明映射为已存储附件。
`asset.ImportContent` 先按现有上传规则检查真实类型、大小和 SHA-256，并持久化全部附件字节，
再调用数据库提交。单附件大小沿用部署的 `MADOC_MAX_UPLOAD_MB`（默认 20 MiB）；缺失、重复、
额外附件、类型 / 长度 / 摘要不一致都会拒绝。读取与实际写入有界，不把附件整体保存在 Go 内存。
数据库记录提交前，附件不能通过正常资产接口访问。

每次尝试拥有独立的 `assets/<workspace>/.imports/<attempt>/` 目录，带有受控 journal 和附件
UUID 文件名。文件及目录刷盘后提交数据库引用；成功后该目录继续作为附件存储位置，不再移动。
重试或并发请求可以产生不同尝试目录，但数据库回执只允许发布一次，其他尝试独立清理。

文件系统与 SQLite 不是同一事务。失败清理使用独立短超时上下文重新检查数据库引用，只删除
本次目录且确认无引用的文件；数据库不可访问时保留目录，不猜测提交结果。后续重试仍通过
持久化回执判断是否已经成功。中途撤权 / 禁用由提交事务再次检查，拒绝时清理本次未发布文件。

服务启动、开始接受请求之前执行恢复清理：只识别合法 Workspace / 尝试 UUID、有效 journal、
白名单内常规文件且没有数据库引用的目录。已提交目录保留；符号链接、未知文件、缺失或损坏
journal 不自动删除。因此极早期中断可能留下少量不可见且未识别的暂存数据，不会生成半组 Item。
恢复扫描只在启动时运行，不与正在上传的请求并发；沿用单实例部署边界。

HTTP 接口为 `POST /api/workspaces/{workspaceId}/imports`，需要 session、CSRF 与写权限。
首个 multipart 字段 `plan` 包含初始快照和附件声明，后续文件字段名为附件目标 UUID，顺序任意。
未知 JSON 字段（包括客户端 storage key）会拒绝。整体传输上限 1 GiB，用于容纳 base64 快照、
JSON 转义与 multipart 开销；解码内容仍受 512 MiB 服务层限制，并不提高 ZIP 选择上限。
该接口单独设置最长 5 分钟读写期限。首次成功返回 201，完全相同请求重放返回 200；新提交后
才通知 Workspace 导航刷新。前端在准备完成后提交，并校验成功响应的根 ID 与结果字段。

## 浏览器导入计划

`preparePortableImport` 将已校验的单 ZIP / 完整包集转换成一次固定的 multipart 请求：
新建根文件夹，分配新的请求 / Item / 附件 UUID，保持目录父级关系，计算附件 SHA-256。
所有附件绑定本次根文件夹，包内多个文档可以共享同一新附件。正文、初始 Yjs 快照、白板
scene 与附件累计受 512 MiB 限制，根文件夹也计入 5000 项上限；准备过程可取消。

链接按整个包集的逻辑路径解析，不以分包文件名为基准。改写已登记的相对附件和内容路径，
保留查询参数 / 锚点；不改写外部、绝对、未打包的引用，也不把越界路径或编码分隔符映射为
包内资源。白板元素中的包内相对链接同样映射，既有绝对链接保持原值。

Markdown 使用活动 schema 解析后修改图片节点、链接 mark 和引用定义，再从同一棵树生成
Markdown 与 Yjs 快照；脚注参与映射，行内代码与围栏代码保持原内容。编译仅解析内容，不把
原文安装到 editor view，因此不会为了导入而请求原始私有或外部图片地址。

准备完成的 FormData 已冻结计划 JSON 的内容，调用方必须保留并在网络结果不确定时重用。
不得重新编译（Yjs 会分配新的客户端 ID），也不得重新分配 Item / 附件 / 请求 ID。

## 确认与失败交互

选择完整包并校验后展示目录与统计，默认新建以包根名称命名的文件夹。用户选择目标目录和
新名称；空名、活动同级重名、目标已删除或目录读取失败时不能确认。服务端在提交事务内
再次检查，处理预览后出现的同名内容、目录删除和权限变化。

- 准备正文 / 快照 / 附件摘要期间可取消，取消后不提交请求。
- 提交期间锁定文件、名称与位置，禁止关闭弹窗，防止重复操作。超过服务端五分钟期限仍未
  得到响应时，浏览器在五分半中止等待并转为结果不确定。
- 首次请求明确返回校验 / 权限 / 冲突错误时，保留预览与输入，允许修正后重新准备。
- 网络中断、服务器错误或成功响应结构无效时，保留原 FormData 并显示“重试确认”。此时
  不允许更改目标、名称或包集；即使后续重试返回拒绝，也不能据此否定最初可能成功的提交。
- 成功确认后刷新目录并显示结果，不自动切换当前编辑器。回执重放明确说明没有重复创建。
- 已打开弹窗期间角色降级时保留结果提示，但禁用写入，最终权限由服务端决定。

待确认请求只保存在当前弹窗内存中，不承诺刷新后的自动重试。浏览器刷新 / 路由离开提供
离开保护；用户主动关闭结果不确定的弹窗需确认重试信息会丢失，之后应先检查目录，不能
把关闭窗口当作撤销服务端导入。

## 当前验证

core 测试覆盖混合嵌套树、乱序输入、初始状态与附件映射、逐表故障注入及回滚后重试、
重复 / 环 / 无效元数据、容量边界、已有 ID / 根名称冲突、跨 Workspace 目标、撤权 / 禁用、
并发同请求只提交一次、新连接回执重放，以及删除后旧请求不重新创建内容。

数据库测试从 schema 8 升级，确认正文、快照、代际、附件与收藏不变，并验证回执生命周期。
维护测试验证完整备份恢复保留导入回执。存储测试覆盖真实字节、后续附件失败、回滚、并发
重试、上传中断 / 撤权、已有文件保护、数据库不可访问时保留及重新恢复、未知文件 / 符号链接
保护。真实 HTTP 验证初始 Yjs 编辑、白板 scene、附件下载、通知、失败零发布、CSRF / viewer
边界与回执重放。独立进程测试在上传中 SIGKILL 后恢复清理，并验证成功导入经过 SIGKILL 和
独立目录备份恢复后仍有原始附件与相同回执。

浏览器验证覆盖引用定义与脚注改写、代码保真、快照中的实际目标、重新解析一致性、编译零图片请求；真实 ZIP 经准备函数和 HTTP 接口导入后可以编辑、刷新保留，附件字节与新链接正确，重复提交不重复创建。既有模板和单篇 Markdown 导入回归通过。

确认界面验证覆盖桌面 / 390px、同名竞争、目标目录删除、取消准备零请求、提交期间撤权、响应丢失后原请求重放、后续拒绝仍保留不确定状态与无效成功响应。真实导出再导入覆盖嵌套目录、同名文档、白板、共享图片，以及 52 MiB 分包的完整附件哈希与新内容链接。
