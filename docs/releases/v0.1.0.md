# Madoc v0.1.0

这是 Madoc 的首个正式版本。Madoc 将协同 Markdown 文档和 Excalidraw 白板放入同一个工作区，以 Go 单二进制、SQLite 和本地附件目录部署，无需 PostgreSQL、Redis 或对象存储服务。

相对 `v0.1.0-alpha.4`（2026-10-07），本版本完成站点管理与受控注册（阶段 5），并补齐空状态、界面节奏与首屏资源压缩。此前的四个 alpha 候选及其远端验收失败记录全部保留在 `docs/RELEASE.md`，未被本版本结论覆盖。

## 本次新增

- 站点设置：注册模式（关闭 / 邀请 / 审批 / 公开）、默认工作区创建能力，以及站点级动作审计；管理页区分可写项与仅展示项。
- 用户管理：账号信息、角色与能力编辑、停用 / 启用、状态标签，以及管理员通过链接审批待审账号与激活页。
- 公开注册与邮箱验证：二次提交式注册（先申请、后设密码），统一受理响应防账号枚举，验证链接不被邮件客户端预取消耗；邀请准入在创建与接受邀请时强制生效。
- 邮件发送全部走部署侧环境变量（`MADOC_SMTP_*`、`MADOC_PUBLIC_URL`），未配置时实例照常运行，仅无法启用公开注册（422 `REGISTRATION_NOT_READY`）；密码只存在于进程内存，另有脱敏诊断接口。
- 全站空状态与首次引导：统一的 `EmptyState`（`page` / `section` / `inline` 三种尺寸与三段式文案），工作区首次为空时的一次性引导可关闭并持久化。
- 前端资源压缩与带指纹文件的缓存。
- 界面节奏：侧栏文档树与大纲栏共用一组间距刻度（面板内边距 12px、行内边距 6px、逐级缩进 16px）；活动记录改为日志式、邀请面板与登录 / 注册页统一外框；页面标题从 30px 下调到 16px；账号菜单弹层与「快速打开与搜索」命令面板的间距重排。

## 本次修复

- `dev.sh` 此前可能启动失败并触及真实数据目录，现使用独立临时数据目录。
- 公开注册流程中 `requestSignup` 的分支缺少 `return`，导致 403 / 422 后继续写入 202、响应体变成两段 JSON 拼接。
- 设置全部接入后仍渲染的「尚未接入的设置」空分区。
- 空状态排版与间距此前各页自写，现统一到设计系统的字体与间距刻度。
- 工作区外壳、账号与管理界面的权限与状态加固。
- 「快速打开与搜索」结果列表缺少下限，结果少时弹窗塌缩、输入过程高度跳动；同时修复 `min-height` 与 grid 拉伸叠加导致的整块空白可点区域。

## 已知问题

- 单实例部署，不提供横向扩容或跨实例实时广播；尚未建立可承诺的容量与性能上限，大语料、长文、数百图形与五人以上并发的基准未建立。
- 历史恢复创建新副本，不覆盖原条目；自动版本有保留与容量规则，手动版本永久保留，历史用量可超过自动建版的软限制。
- 本地待提交草稿依赖当前浏览器的站点数据，清除站点数据会删除本地副本；整站离线启动尚未提供，本地草稿不能替代完整备份。
- 工作区删除仍永久删除；条目与目录的普通删除进入回收站。重要数据仍需独立备份。
- 只读分享固定单项手动版本，不提供公开目录或完整发布站点；已被访客读取或下载的副本无法收回。
- 评论绑定整篇内容，暂不支持段落锚点、回复与提醒。
- 浏览器回归以 Chromium 为主，Safari / Firefox 与真实移动设备尚未完整验收；构建仍保留按需加载大 chunk 提示。
- 公开注册的 SMTP 链路在测试中使用自建最小 SMTP 服务端跑通，未对接真实邮件服务商。

## 安装

镜像：`ghcr.io/mahoo12138/madoc:v0.1.0`，目标架构为 `linux/amd64` 与 `linux/arm64`。

```sh
docker pull ghcr.io/mahoo12138/madoc:v0.1.0
docker run -d \
  --name madoc \
  --restart unless-stopped \
  -p 127.0.0.1:3000:3000 \
  -v madoc-data:/data \
  ghcr.io/mahoo12138/madoc:v0.1.0
```

此命令供同一主机上的 HTTPS 反向代理接入。Madoc 自身提供 HTTP，生产 Cookie 带 `Secure` 标记；浏览器必须通过 HTTPS 使用，代理同时转发页面、`/api` 和支持 WebSocket Upgrade 的 `/ws`。不要在生产环境启用 `MADOC_DEV=true`。

首次打开 HTTPS 站点时创建管理员，填写姓名、邮箱和至少 8 个字符的密码；没有默认凭据。初始化完成后使用邮箱和密码登录。`/healthz` 是健康检查入口。

`/data` 持久卷保存 `madoc.db`、`assets/` 与 `server.secret`。服务密钥权限为 `0600`，应与数据库、附件一起保留；重建容器需继续挂载原卷。Release 同时提供 Linux / macOS 的 amd64 / arm64 单二进制压缩包、SHA256 校验清单和镜像摘要。二进制已经嵌入前端，默认数据目录为 `./data`，可通过 `MADOC_DATA` 指定，详见 [构建与部署](https://github.com/Mahoo12138/madoc/blob/v0.1.0/BUILD.md)。

## 备份与升级

升级前让协作者确认已保存、关闭旧编辑页，并下载仍需保留的未同步副本。停止服务后，用当前版本执行 `madoc maintenance backup`，再将生成的完整备份复制到数据卷之外。不要仅复制活跃 WAL 数据库的主 `.db` 文件。

替换为目标版本后继续使用原数据卷；服务与内嵌前端一起升级。启动后检查健康接口、登录、原工作区、文档图片与白板，再重新打开页面。启动时应用增量迁移；回退应停服、恢复升级前完整备份，并使用对应旧版本，不能让旧二进制直接访问升级后的数据库。

恢复到独立空目录前，先用目标数据目录启动一次服务并在健康后停服，无需创建管理员，再执行 `madoc maintenance restore /path/to/backup-directory --confirm`。恢复会先保留当前数据，失败时回滚。旧 AFFiNE / BlockSuite 数据不自动转换，也不自动删除，详见 [迁移说明](https://github.com/Mahoo12138/madoc/blob/v0.1.0/docs/MIGRATION.md)。完整命令见 [备份步骤](https://github.com/Mahoo12138/madoc/blob/v0.1.0/BUILD.md#backup)。

发布验收必须绑定实际发布提交。完整检查顺序和历史验收记录见 [发布检查](https://github.com/Mahoo12138/madoc/blob/v0.1.0/docs/RELEASE.md)，此前记录不能替代本次目标提交的结果。
